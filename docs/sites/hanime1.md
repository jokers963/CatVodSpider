# Hanime1 实现档案

当前实现：`js/hanime1.user.js` 3.0.0，正式脚本查询版本 `v=3`。

## 为什么采用轻量 DOM 方案

Hanime1 的搜索页同时承载分类、筛选、分页和卡片，详情页直接输出多个 MP4 source。首页因此只返回固定分类/筛选元数据，不等待影片卡，既减少 WebView 工作量，也避免宿主自动生成“推荐”页。

## 路由与数据流

| GM 方法 | 页面 | 提取方式 |
| --- | --- | --- |
| `homeContent` | `/search?page=1&sort=最新上市` | 返回 10 个真实分类和三组筛选 |
| `categoryContent` | `/search?genre=...&page=...` | 抓 `/watch?v={id}` 卡片和分页 |
| `searchContent` | `/search?query=...&page=...` | 同一套卡片与分页逻辑 |
| `detailContent` | `/watch?v={id}` | 读取所有 HTTPS `video source[type=video/mp4]` |

分类 ID和筛选值使用网站的繁体原值，显示名称使用简体；放进 URL 前统一编码。三组筛选为排序、发布日期和时长。列表按视频 ID 去重，标题兼容 `.title`、`.home-rows-videos-title` 和图片 alt。

详情按 `source[size]` 数值从高到低排序，生成多线路，例如 720、480。播放是普通 MP4 直链，不需要 `playerContent`、嗅探或 GMSubs 媒体代理。

正式配置屏蔽 CSS、字体、统计和已知广告资源，并关闭列表图片网络加载，以减少页面初始化开销。未强制使用统一 1.5:1 卡片样式，因为实测会裁切该站封面。

## 验证页处理

脚本每 500 ms 检查业务结果，最多等待 25 秒。检测到验证页面时显示 WebView供用户手动处理；没有可播放内容时返回明确消息。不会自动点击验证。

## 测试与实机结论

`js/hanime1.nav.test.cjs` 覆盖分类、筛选、分页 URL、搜索分页和正式版本；`js/new-sites.test.cjs` 覆盖多清晰度排序。手机内置播放、自然进度、快进、返回重播及搜索翻页均已通过。

## 可复用经验

- 首页只需要导航时，不要为了“看起来完整”额外抓一页影片。
- 显示文本和网站真实筛选值可以分离；请求必须保留网站认可的原值。
- 原生 `<video><source>` 已给出多清晰度时，直接排序返回比重新探测清单更可靠。
- 卡片比例应由实物封面决定，不能为了跨站统一而裁切内容。
