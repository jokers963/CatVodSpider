# 肉视频（Rou）实现档案

当前实现：`js/rou.user.js` 1.0.5，正式脚本查询版本 `v=6`。

## 为什么需要 userscript + GMSubs 代理

Rou 的列表可以从页面 DOM 获取，但单视频播放地址藏在页面 hydration 脚本中，媒体清单和分片又伪装成 PNG。userscript 负责发现同源 `/api/hls/{id}`，`GMSubs` 只对精确的 Rou HTTPS 路径启用本地代理并解包；其他站不受影响。

## 内容模型

首页只返回分类和筛选，不等待卡片，从而加快进入速度并避免宿主生成“推荐”页。

- 视频分类：`/v` 和 `/t/{分类}`，支持最新、观看、喜欢排序。
- 剧集库：`/series`，支持排序、连载状态和题材筛选。
- 视频卡：从 `/v/{id}` 链接读取，标题以可见 `.clamp-2` 为准，不能依赖图片 alt。
- 剧集卡：从 `/s/{id}` 链接读取。
- 搜索：当前页面抓视频，再请求同一搜索 URL 的 `tab=series` 页面并合并、去重两类结果。

Rou 没有统一使用 `rect / 1.5` 样式，因为其封面比例不同；曾统一样式后出现裁切，已经回退。

## 视频与剧集播放地址

单视频页面查找形如 `ev:$R[...]={d:"...",k:N}` 的 hydration 数据。若前端已从 DOM 删除脚本，就重新请求当前 HTML。解码步骤是 Base64 → 每个字符减偏移量 → JSON → `videoUrl`，最终只接受当前 origin 下的 `/api/hls/` 路径。

剧集页直接把每个 `/v/{id}` 集数映射为 `/api/hls/{id}`，按“第 N 集”生成播放列表。重复集数链接会在生成前按有效编号筛选。

## 伪 PNG HLS 原理

Rou 返回的 `image/png` 实际含自定义 `roUd` chunk：标志位决定 payload 是否经 zlib/deflate，解包后内容才是 `#EXTM3U` 或 MPEG-TS。`GMSubs` 的处理流程为：

1. 仅匹配无用户信息的 `https://rou.video/api/hls/`。
2. 把播放 URL替换为宿主本地 `/proxy`，显式标为 HLS。
3. 解包主清单和子清单，解析相对 URI并改写为代理 URL。
4. 解包分片并以 `video/mp2t` 返回；分片请求只保留 User-Agent，避免无必要传播 Cookie、Origin 和 Referer。
5. 清单限制 8 MiB、解压输出限制 64 MiB，读取失败关闭上游流。

## 测试与实机结论

`js/new-sites.test.cjs` 覆盖分类、筛选、视频/剧集卡、页数、合并搜索、hydration 解码和剧集线路。`GMSubsTest` 覆盖精确域名边界、PNG chunk 解压、TS 检测、清单改写、请求头裁剪、大小上限和失败关流。手机实播验证包含自然进度、快进和返回后从接近开头重播。

## 可复用经验

- 页面数据被前端删除时，回源当前 HTML通常比模拟整个前端运行更小、更稳定。
- 自定义媒体封装应在精确域名/路径上做最小代理，不要按 Content-Type 全局猜测。
- 先证明伪装载荷的真实格式，再决定解包层；拿到 URL 不等于播放器能读。
- 视频和剧集是不同内容模型，搜索合并时应保留各自 ID 前缀。
