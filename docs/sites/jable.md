# Jable 实现档案

当前实现：`js/jable.user.js` 1.0.10，正式脚本查询版本 `v=12`。分类翻页的专项故障记录见 `docs/handovers/2026-10-02-doubao-to-codex-jable-pagination.md`。

## 为什么采用 DOM + 两套分页策略

Jable 的列表、分类和 HLS 变量都能从页面取得，但分类与搜索使用不同的分页机制：分类是 KVS 异步分片，搜索是页面内 AJAX 且 URL 不变化。一个通用的 `?page=` 模板无法覆盖两者，因此脚本分别处理。

## 路由与数据流

| GM 方法 | 页面 | 提取方式 |
| --- | --- | --- |
| `homeContent` | `/` | 从分类图片卡动态读取 `/categories/{id}` |
| `categoryContent` | KVS `mode=async` 分片 | 抓 `/videos/{id}` 卡片并按批量判断是否继续 |
| `searchContent` | `/search/${key}/` | 在同一 WebView 中点击分页控件后抓当前 DOM |
| `detailContent` | `/videos/${id}/` | 读取 `unsafeWindow.hlsUrl`，失败时扫描内联脚本 |

卡片解析会按视频 ID 去重，并兼容 `.video-img-box`、`article`、`li` 等容器。详情只接受 HTTPS 且以 `.m3u8` 结尾的地址，作品编码和标题放入线路名供字幕匹配。

## 分类分页

KVS 分片没有分页 DOM。满批（当前约 24 条，代码以 `>=20` 判断）时上报 `pagecount=9999`，让宿主继续请求下一分片；短批上报 1，空页自然结束。普通整页若有真实分页链接，仍以页面最大页码为准。

这是有明确上限的惰性策略：站点批量规则改变时，应更新满批阈值或改读接口总数，而不是把 9999 扩散到其他站。

## 搜索分页

搜索翻页不改变 URL。`searchPageDrive(pg)` 读取当前激活页，点击目标页或可推进分页窗口的最大页码，等待 AJAX 替换 DOM，并连续观察稳定后才抓结果。最多点击 24 次；目标不可达时返回空列表，避免重复第一页形成无限滚动。

## 验证页处理

Cloudflare 验证出现时显示 WebView，等待预算从首次发现验证起算 60 秒。真实内容优先于残留验证标记。验证跳转丢失 GM 方法参数时会立即返回“请求参数异常”，避免 WebView 永久转圈。正式配置还屏蔽已知广告/统计域名并关闭列表图片网络加载。

## 测试与实机结论

`js/adapters.test.cjs` 覆盖 HLS、60 秒验证预算、残留验证标记、未知方法、分类满批/短批/普通分页，以及搜索首页、第二页和不可达页。用户已验证分类和搜索翻页；WebView 更新后内置播放、快进和返回重播通过。

## 可复用经验

- 先确认翻页是否真的改变 URL；不改变 URL 时必须驱动页面状态或直接调用其 AJAX 接口。
- 分片响应没有分页 UI，不能复用整页 `pageCount()`。
- 不可达页应返回空列表终止，不要悄悄重复上一页。
- 验证等待从“发现验证”计时，比从导航开始计时更符合用户实际操作窗口。
